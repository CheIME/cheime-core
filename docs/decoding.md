# 拼音联合解码

当前解码器在同一张有向无环图中处理：

- 拼音音节切分；
- 模糊音和简拼变体；
- 可选的 Damerau 编辑纠错；
- 静态词典与用户词典词元；
- 量化 n-gram 语言模型分数；
- 补全、来源和用户学习信号。

纠错不是“先修改拼音，再执行汉字转换”。输入原路径和纠错路径会同时保留，
由词典权重、语言模型和输入路径代价共同决定候选顺序。即使错误输入仍然可以
切分成合法拼音（例如 `yi si` 与 `yi shi`），纠错路径也不会被提前删除。

## 配置

纠错默认关闭，因此旧配置的候选和性能路径不受影响。

```yaml
engine:
  segmentors:
    - type: pinyin_syllable

  pinyin_correction:
    enabled: true
    # 运行时限制为 1..=2
    max_edit_distance: 1
    # 每个输入位置最多生成 64 条；默认 16
    max_candidates_per_start: 16
    # 每次编辑的定点代价；负数和 0 会被安全归一化
    edit_penalty: 500000
```

支持的单次编辑包括插入、删除、替换和相邻字母交换。所有外部数值都会在进入
实时路径前归一化：

- `max_edit_distance` 限制在 1 到 2；
- `max_candidates_per_start` 最大为 64；
- `edit_penalty` 最小为 1；
- 解码器使用饱和整数运算，不会因为分数溢出而 panic。

纠错图使用按输入代价排序的 K-best 遍历。有代价的图每个起点最多考察 64 条
音节序列；普通无纠错图仍保留原来的 1024 条上限。

解码器不会把原始词频简单理解成可跨词相加的概率。完整输入能够直接命中一个
词元时，该精确词元会先于由简拼、模糊音拼出的多词元路径。例如 `zhen` 的
`真 / 阵 / 震` 不会再被高频的 `zhe + n` 组合候选挤出首屏。

长输入使用词典前缀剪枝：如果当前音节序列不可能成为任何更长词元，搜索会在
该位置结束，后续内容交给下一词元继续解码。短输入跳过这项检查，避免一次额外
的有序索引查询。词典的 Top-K 前缀查询只为最终保留的候选分配字符串。

## 语言模型

`language_model` 模块提供线程安全的定点分数接口。默认
`NullLanguageModel` 永远返回 0，保持原排序；`BackoffNgramModel` 按
trigram、bigram、unigram、unknown 的顺序回退。

运行时可通过 `PipelineFactory::build_with_language_model` 注入模型。模型训练、
量化和文件加载不在按键实时路径中进行。

## 自动评价

`evaluation` 模块通过 `InputPipeline::refresh` 在无前端、无 TSF、无 DLL
注册的进程中计算：

- Top-1；
- Top-K；
- 分页选词成本；
- KySS 风格的理想/实际选词成本比。

选词成本使用 `floor(rank / page_size) + 1`。评价器通过最短路寻找完成目标文本
的最低成本选词序列，因此可以正确比较“一次选择长词”和“多次选择单字”。

## 当前性能基线

在 539,071 条 `rime_ice` 词典和 release 构建下，本地 Criterion 基准结果：

- 普通解码 `nih`：约 78 微秒；
- 普通解码 `nihao`：约 14 微秒；
- 歧义输入 `xianshi`：约 36 微秒；
- 49 字节长输入：约 6.9 毫秒；
- 纠错开启 `nihao`：约 0.55 毫秒；
- 纠错开启 `shenem`：约 2.2 毫秒；
- 单独生成 `shenem` 纠错切分图：约 0.22 毫秒。

因此纠错仍保持默认关闭。后续优化重点应放在词典前缀剪枝和带语言模型状态的
惰性词元展开，而不是继续增加全图候选数量。
